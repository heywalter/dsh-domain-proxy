## 1. 代理地址与端口配置

在 **本机代理地址** 中填入本地代理软件提供的 HTTP(S) 监听地址，例如：

| 示例地址 | 说明 |
| :--- | :--- |
| `http://127.0.0.1:7890` | 本机 HTTP 代理（Clash / FlClash 常见默认端口） |
| `http://127.0.0.1:7897` | 本机 HTTP 代理（自定义端口） |
| `http://localhost:8080` | 本机 HTTP 代理（本地网关） |
| `https://127.0.0.1:8443`| 本机 HTTPS 代理（代理证书需受系统信任） |
| `http://[::1]:8080` | 本机 IPv6 回环 HTTP 代理 |

### 协议说明与常见误区
- **协议类型**：此处的协议指“DSH 连接本地代理软件”所使用的传输协议，**而非目标 API 的协议**。现代代理软件通常通过 HTTP CONNECT 隧道代理 HTTPS 请求，因此即使访问 `https://` 的 API 域名，本地代理地址也通常填写 `http://`。
- **协议兼容性**：仅支持本地 HTTP 和 HTTPS 协议；暂不支持 SOCKS5、PAC 脚本、远程局域网代理或在 URL 中内嵌认证信息（如 `user:pass@`）。
- **端口提示**：`7890` 仅为示例默认端口，请根据实际使用的代理客户端（如 Clash、v2rayN、Sing-box 等）的本地监听端口填写。

## 2. Provider 识别与域名分流规则

### 域名来源与解析
- 插件会自动扫描当前 DSH 中已启用的 Provider 目录与配置项，提取出显式配置的 API `baseURL` 主机名。
- 若 Provider 属于尚未配置的休眠项，或使用了环境变量动态注入的地址，则不会自动出现在下拉列表中，可直接在输入框中手动键入目标域名。

### 规则生效机制
- **草稿机制**：在界面中添加或删除域名只会在当前页面生成草稿，点击 **保存设置** 后才会真正持久化并热重载至网络分发器。
- **共用域名**：分流基于域名生效。如果多个 Provider 配置了相同的域名（例如同一个自建反代网关或聚合服务），它们将共用该域名的分流规则。
- **匹配模式**：最多支持配置 32 个域名。默认采用**精确匹配**（仅匹配 `api.example.com`）；勾选 **包含子域名** 后，该域名下的所有子域名（如 `v1.api.example.com`）均会被匹配。
- **输入格式**：仅填写纯主机名（FQDN），请勿携带 `http://`、路径、端口号或 `*.` 通配符。

## 3. 连通性测试与网络路径机制

### 检查连接（Doctor Check）
- 点击 **检查连接** 时，插件会依次向列表中各域名的 HTTPS 根路径发送一个轻量级的无鉴权 `HEAD` 请求（每个域名超时时间约为 8 秒）。
- **返回结果判定**：收到 HTTP 200、401、404 或 503 均说明网络传输层已成功通过代理连通目标服务器。这仅用于验证代理通道可达，**不包含模型 API 鉴权，也不会触发模型测试或消耗 Token 额度**。

### 出口节点与原生路径
- **分流边界**：插件负责将命中的域名路由至本地代理端口；实际出站流量使用哪个节点（如香港、日本、美国等）完全由本地代理软件的分流规则或策略组决定。
- **未匹配流量**：未加入分流列表的所有请求（包括其他 Provider 调用或外部网络请求）均保持原有路径不变（如果系统已开启全局 TUN 或系统代理，原有路径可能已包含对应代理）。

## 4. 调用观测与指标口径

### 开启与存储机制
在插件设置中勾选 **记录最近调用** 并保存后，插件会在日常对话过程中自动记录每次模型流式调用的链路与性能元数据：
- **纯内存保存**：最多在内存环形队列中保留最近 100 次调用的元数据。
- **严格隐私保护**：仅记录耗时、吞吐量和分发节点信息，**绝对不记录**对话正文、提示词（Prompt）、模型回答、请求头或 API Key。
- **生命周期**：关闭记录开关、点击“清空记录”或重启 DSH 客户端后，记录将彻底销毁，不产生任何本地磁盘文件。

### 指标定义口径

| 指标项 | 统计口径与定义 |
| :--- | :--- |
| **首内容等待（TTFT）** | 从客户端开始消费模型流，到接收到首个非空文本、思考过程（Reasoning）或工具调用参数增量的时间。不同于底层的 TCP/HTTP 首字节时间。 |
| **流式生成速度** | 适配器输出有效 Token 总数 ÷ 首个内容块开始到最后一个内容块结束的时间跨度（Token/s）。仅在调用完整成功且采样充分时计算。 |
| **单次调用总耗时** | 单次模型调用的端到端总时间（包含初始首字等待），不包含后续工具执行或本地代码运行的时间。 |
| **最长内容间隔** | 流式输出过程中相邻两个数据增量之间的最大停顿时间。有助于排查网络抖动或服务端偶发卡顿。 |
| **Token 用量** | 模型适配器直接上报的输入/输出用量数值；若服务端未返回相应字段则显示“未知”。 |
| **重试次数** | 当前版本尚未对适配器底层的自动重试建立精准关联，统一显示为“未知”。 |

> **提示**：计时统计包含客户端适配器处理与排队时间。因不同会话的任务复杂度、上下文长度及服务端缓存状态存在差异，数据主要用于排查链路与卡顿，不建议作为严格的基准测试数据。

## 5. CLI 诊断工具与运维管理

### 独立 CLI 诊断
项目内置了免启动 DSH 的独立命令行检测工具，可用于在终端快速验证代理连通性：

```sh
node bin/cli.js doctor --domain api.example.com --proxy http://127.0.0.1:7890
```

- **退出状态码**：
  - `0`：传输层连接成功。
  - `1`：网络或传输层连接失败。
  - `2`：命令行参数格式无效。

### 插件升级与卸载
- **Desktop 客户端**：通过内置的 **Plugins** 管理器进行常规安装、更新与卸载。建议在当前没有进行中的模型调用时进行更新，更新后重启客户端。
- **Web CLI Profile**：支持通过 DSH 命令行管理：
  ```sh
  # 安装离线包
  dsh plugin --profile web add /path/to/dsh-domain-proxy-0.1.1.tgz
  # 移除插件
  dsh plugin --profile web remove dsh-domain-proxy
  ```
- **配置清理**：DSH 在卸载插件后可能会保留用户的配置项。如果计划在卸载后彻底恢复默认网络，建议在卸载前先在界面中关闭“启用域名分流”并保存。

## 6. 运行边界与兼容性

- **网络栈覆盖**：本插件通过挂载 DSH 后端全局 `Undici Dispatcher` 实现无侵入分流，覆盖标准的全局 `fetch` 与官方模型适配器。
- **边界限制**：如果第三方扩展或自定义 SDK 绕过全局调度器使用了独立的私有网络栈、直接建立 WebSocket 连接或通过子进程发起请求，这些流量可能不在分流与观测范围内。
- 更多安全与验证细节请参阅 [安全说明](../SECURITY.md) 与 [验证范围](VALIDATION.md)。
